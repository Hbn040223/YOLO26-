# 双目端侧加速的服务器验证

在 KITTI Stereo 2015 的固定 40 帧验证集上完成了全图基线、顶部裁剪 A0–A3、双目包含抑制 C0/C1。精度和探索性延迟使用 RTX 6000 Ada、PyTorch 2.1.2、FP32，工作版本为 `be1601e`。服务器计时用于验证流程和记录运行点。开发板实测和通过判定待后续实验。

- 验证集 `pilot_random_seed17/val.json` 的 SHA-256 为 `4e5a06c19d036c9234ed11c68e9ff8dd224dc610005e47aa5828d01975753651`。双目覆盖率使用原图 GT、同类一对一双目 IoU ≥ 0.50。近车沿用有效视差标定距离 <10 m。GT ID 由帧名和同一数据加载流程中的零基 GT 行号组成。
- 端到端包含图像读取与归一化、拷贝、推理中的裁剪、坐标恢复及输出传回主机。每组预热 2 次，随后在同 40 帧交替测量，每帧每组 1 次。分段使用单独的同步插桩轮次。RTX 6000 Ada 为共享服务器，默认频率和 300 W 上限。

## 代码入口

- `scripts/infer.py` 支持 `--crop-top-px`、`--paired-nms --containment-suppression`。NPZ 中的框和 RoI 纵向原点为原图坐标。裁后反投影时，左右主点纵坐标分别减去 `crop_top_px`。水平视差仍使用原图像素单位。
- `scripts/evaluate_edge_acceleration.py` 生成 A、C 的逐帧精度、GT 几何表和包含事件。传入 `--calibration-zip` 启用原有 <10 m 近车队列。两份权重分别运行以保留独立前景分母。
- `scripts/benchmark_edge_acceleration.py` 使用 `--stage baseline|crop|containment` 切换对照，`--profile` 在端到端计时之后单独测分段。
- `scripts/benchmark_edge_backbone.py` 使用相同冻结 RoI 负载比较 V2 和 V3-Small 原型。两边都执行检测头，随后将同一份 RoI 送入实例头，省略在线解码和 NMS。支持实际 C0 负载和 6、9、50 对受控负载。
- `scripts/export_edge_frontend.py` 按原图尺寸和裁剪量导出静态 ONNX。对高 375、宽 1242 的输入，0/64/96/128 四档均通过 ONNX 检查。合成输入下，ONNX Runtime CPU 与 PyTorch CPU 的八个前端输出最大绝对差为 `7.2e-5`。`--trtexec` 可用 TensorRT 8.6–10.x 构建 FP32 和 FP16 引擎及输出层信息。[NVIDIA TensorRT 10.x 引擎检查文档](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/inference-library/engine-tools.html)
- `scripts/benchmark_edge_tensorrt.py` 在引擎外复用普通 paired NMS 和实例头，同时比较保留 ID 与冻结负载前向。独立插桩记录双目 IoU、判定掩码 D2H、CPU 贪心筛选和 RoI/Mask/iDisp。

完整 JSON 存放在服务器实验输出目录，工作区副本在 `outputs/stereo-edge-server/`。当前实验保留两个优化开关的关闭默认值。V3 微调、TensorRT 引擎运行、CUDA Graph 和组合验收等待相应评估条件。
